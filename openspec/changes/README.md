# Proposed changes

Create one folder per accepted-contract change. Include:

- proposal.md: problem, intended outcome, requirements, non-goals, and affected current specs.
- design.md: decisions, interfaces, compatibility, migration, security/balance, and alternatives.
- tasks.md: bounded implementation issues, file ownership, dependency edges, acceptance commands, screenshots, and unresolved risks.

Keep implementation-only fixes in their issue when they do not change a durable contract. Do not treat a proposal as authorization; exact agent:ready remains the dispatcher gate.
