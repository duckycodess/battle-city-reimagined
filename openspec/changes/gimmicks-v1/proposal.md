## Goal and representation

Opt-in v2 authored stages retain the 16×16 grid. Append codes `9`, `A`, `B`, `C` for north/east/south/west conveyor and `D` for a paired pad, without changing classic codes `0`–`8` or the three bundled stage files. An explicit one-character sim Tile ↔ row-code mapping replaces decimal-value-derived row encoding in sim and server; the content TileCode uses the same characters, and editor artwork uses the mapping instead of `int(code.value)`. TileGrid.to_rows and snapshot grid_rows remain exactly the same for classic tiles. Zero or exactly two `D` cells are valid; row-major order identifies the unique pair. Reject 1 or >2, incompatible pack/level schema versions, unsupported codes, malformed rows and unsupported content before play with specific validation errors; never fall back to a different stage or silently replace tiles. Keep v1 schema/loader and classic hashes byte-for-byte stable; a v1 consumer must reject explicitly v2 content and terrain, not reinterpret or paint blank. Content loader enforces pad count after JSON Schema shape validation; Stage.create independently enforces pair count for direct sim callers. The renderer consumes an already validated Stage and does not revalidate pair count. The v2 JSON Schema and loader accept v2 only when version is explicitly 2; make editor save/export produce a valid v2 pack/level when gimmick codes are used, and preserve v1 when not. Content remains declarative and headless. Put a separate v2 sample pack and level under packages/content/src/battle_city_content/packs/ and levels/ (never extend classic.json or alter load_bundled_pack). ## Deterministic movement and ordering

Tank movement remains inside existing phase 5; restructure the loop so idle belt riders participate. The tank's center is `(x + tank_size // 2, y + tank_size // 2)` in integer world pixels; tile activation is determined by the center's grid cell, not the entire 16px body fitting in one 16px tile. Each fixed tick handles tanks in ascending tank ID. For each tank: record its initial center cell; apply its one commanded movement through the existing collision/bounds rules (blocked command does not suppress later conveyor push); if the recorded cell is a conveyor, attempt **one** `tank_speed` push in its arrow direction with the same collision/bounds checks against the current positions of other tanks. The conveyor direction does not change facing; even an idle tank is pushed; entering an arrow mid-tick does not activate it until the next tick. No chain push when leaving one arrow for another. A push blocked by a wall or tank is cancelled, not the accepted command, and never tunnels or overlaps. Projectile updates and existing combat/pickup phases remain after tank movement in their established ordering. A commanded 2px move plus 2px conveyor push may yield 4px displacement in one tick; no new Rules field is needed. The initial center cell is recorded at start of movement phase after any existing spawn/respawn phases.

After the command and possible push for that tank, if its final center cell is a pad and differs from its recorded initial center cell, attempt **one** transport to the opposite pad, preserving its pixel offset relative to the source cell origin. Check whole-body bounds, tiles and occupancy with the same tank collision routine; if blocked, stay at the reached entry position with no deferred retry or displacement of another tank. Arrival does not chain on the same tick and a stationary tank on a pad does not repeatedly jump; leaving and re-entering a pad on a later tick permits another attempt. Both factions use identical rules; content spawn placement remains empty-ground-only; direct sim spawn commands retain their existing collision/placement contract, including potentially traversable gimmick tiles. No transport triggers merely from a spawn; phase-5 initial cell is recorded after spawn/respawn. No mutable pad flag, cooldown, new simulation phase, or player-selected destination. Destination contention resolves by ascending tank ID and already-updated bodies.

Projectiles treat arrows/pads exactly as empty traversable ground: no redirection/teleport, changed speed or damage. Existing move events describe commanded motion; append a TankMoved for successful push or transport (position is final for that displacement, facing remains the tank's facing even on a perpendicular push) and a TankMoveBlocked for attempted but blocked push/transport using the existing event vocabulary. An idle arrow rider still receives movement and observable events; do not add wire event kinds. Existing mirrors/brick/base, projectile collision and forest concealment remain unchanged. Arrows/pads have no concealment and no powerup/scoring effect. AI predicts command/push/entry/arrival with the same collision and occupancy semantics and chooses only legal tick intents; it cannot rely on an occupied exit as a shortcut, and uses bounded seeded planning without perfect-information visibility changes. Preserve byte-identical AI decisions on gimmick-free stages. Existing AI has bounded roam/clearance prediction rather than a full path planner: pathing acceptance tests cover push/arrival-aware legal decisions and blocked exits, not invented global routing.

## Version and authority

The canonical simulation state format remains version 1, with newly appended tile bytes only; there are no new entity fields or reordered old fields. For any identical v1 state/input, canonical bytes and hash are unchanged. New terrain is meaningful only in a v2 content/rules session; replay/session metadata must identify content schema and exact pack/rules (and protocol version for network replay), so v1 consumers reject incompatible v2 rather than interpreting new bytes as v1. Do not bump PROTOCOL_VERSION (already 2), SNAPSHOT_VERSION (1) or CANONICAL_STATE_VERSION (1). ContentRef.content_schema_version (1 vs 2) is the negotiated compatibility signal; existing content mismatch rejection is the upgrade path. Validate grid alphabet/width strictly conditional on that agreed content version, retaining all v1 classic rows. Never send v2 tile codes disguised as v1, or leak unsupported v2 content into a v1 session. The server exclusively applies conveyor displacement, teleport and resulting snapshots. Client input remains tick-indexed intents, never movement/state claims. V2 snapshots preserve tile codes and content version through server translation, transport validation and client translation; terrain delta/keyframe paths cannot erase cues. No new replay file format: test deterministic run_ticks/golden vectors and record ContentRef in existing session/match metadata.
