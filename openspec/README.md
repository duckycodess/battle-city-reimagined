# OpenSpec-style workflow

specs/ records accepted, durable product and engineering contracts. Each capability has one current spec.md.

changes/ records proposed contract changes. A change uses proposal.md, design.md, and tasks.md; accepted changes update affected current specs. Remove completed proposal folders only after the current specs contain accepted decisions and implementation issues link the relevant spec sections.

Implementation issues remain the executable work queue. Specs describe what must hold; issues bound work, allowed files, dependency edges, acceptance commands, screenshots, and remaining risks.
